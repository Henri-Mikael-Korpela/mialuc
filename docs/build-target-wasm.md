# Build target: WebAssembly

The `wasm` and `wat` targets of `mialuc build` write a WebAssembly module, as a binary (`.wasm`) and as text (`.wat`). This document describes what they build and how. See [mialuc](mialu-cli.md) for the commands, [Getting Started](getting-started.md) for building the compiler, and the [language specification](mialu-programming-language.md) for the language itself.

The programs in [test-code/wasm](../test-code/wasm) are for these targets, and the [playground](playground.md) compiles and runs them in the browser.

## Foreign procedures

A foreign procedure is declared in a `foreign js` block, see [Foreign procedures](mialu-programming-language.md#foreign-procedures).

The target makes a foreign procedure an imported function of the module. The name of the object in `import foreign js` is the name of the module of the import, and the name of the procedure is the name of the import. So the program above needs an object of imports like this when it is instantiated:

```js
const imports = {
    functions: {
        alert: (address, length) => {
            const bytes = new Uint8Array(instance.exports.memory.buffer, address, length);
            console.log(new TextDecoder().decode(bytes));
        },
    },
};
const { instance } = await WebAssembly.instantiate(bytes, imports);
```

The function gets the parameters as the target passes them everywhere: an `Int` is a `BigInt`, a `Bool` is the number 0 or 1, a pointer is one number, the address of what it points to in the memory of the module, and a `Str` is two numbers, the address of its bytes in the memory of the module and their count, which is how the function above reads the message. The memory is the one that the module exports as `memory`, which a program has when it has a string or an array type. A function that returns something returns it in the same way, so a procedure that returns an `Int` is a function that returns a `BigInt`, and one that returns a `Str` returns an array of the address and the length. If the object does not have the function, `WebAssembly.instantiate` rejects with a `LinkError` that names it.

## Code generation

The `wasm` target writes a WebAssembly binary module. It imports its foreign procedures from JavaScript, so a procedure of a `foreign libc` block is an error, and so is a call of `str_to_c_str` whose argument is not a string literal or a constant that is a string. Every constant definition becomes a function that the module exports under the name of the constant. A constant that is a value becomes a function without parameters that returns the value as a value of its type, or of its default type when it is untyped, so `LIMIT :: 200` returns an `Int` and `GREETING :: "Hello"` a `Str`, which JavaScript can call to read it. A procedure that uses the constant does not call that function: the compiler worked out the value, and a constant expression is the one instruction that pushes it as a value of the type that its place wants, so `LIMIT * 2` is `i64.const 400`, and `-1` and `0 - 1` are `i64.const -1`. A signed integer literal such as `-5` is the same `i64.const` with a negative value. A call of a procedure is the `call` instruction with the function of the procedure, after the instructions of the arguments, which are pushed in order. A `Str` argument or result is two values, as it is for the exports. A call that is a statement is followed by a `drop` for every value that the procedure returns, which is one, or two for a `Str`. `Int`, `Bool`, `Byte` and `Str` are the basic types that the target supports, and then the structs, the pointers to any of them, and the arrays and array slices of any of them.

`Int` is a 64-bit integer (`i64`), so JavaScript passes and receives it as a `BigInt`. An untyped integer is `i64.const` of its value where an `Int` is wanted, whatever its base, since the compiler has worked out the number, so the `wat` target shows `0xFF` and `0b1111_1111` as `i64.const 255`. The arithmetic is the one of [Integers](mialu-programming-language.md#integers), with the signed `i64` instructions. Division traps, which makes the call from JavaScript throw a `WebAssembly.RuntimeError`, when the divisor is zero, or when the smallest `Int` is divided by -1, because the result does not fit.

`Rune` is a 32-bit integer (`i32`), the code point of a character, from 0 to 0x10FFFF, so JavaScript passes and receives it as a plain number, and not as a `BigInt`, and `String.fromCodePoint(rune)` and `string.codePointAt(0)` convert it to a character and back. A rune literal, such as `'A'`, `'芋'` or `'🚀'`, and one that has an escape sequence, such as `'\n'` or `'\u0123'`, is `i32.const` of its code point, so the `wat` target shows `i32.const 128640` for `'🚀'` and `i32.const 10` for `'\n'`. Runes are compared with the unsigned instructions `i32.lt_u`, `i32.le_u`, `i32.gt_u` and `i32.ge_u`, and with `i32.eq` and `i32.ne`. A cast of a `Byte` to a `Rune` is nothing, because both are 32-bit integers, and a cast of a `Rune` to an `Int` is `i64.extend_i32_u`. A cast of a `Rune` to `[4]Byte` keeps the rune in a scratch local, stores a zero word in the 8 bytes of the frame that the cast has, as an array literal has its elements there, and then stores the bytes of the UTF-8 encoding with `i32.store8` in nested `if` and `else`, which compare the rune with 0x80, 0x800 and 0x10000, with `i32.lt_u`: each byte is the rune moved down with `i32.shr_u`, kept to its lowest 6 bits with `i32.and` unless it is the first, and has `i32.or` with its marker, 0x80 for the bytes after the first, and 0xC0, 0xE0 or 0xF0 for the first of two, three and four. The value of the cast is the address of the 8 bytes, so the module has a memory and a stack for it, as it has for an array literal. The default value is `i32.const 0`. A rune is one slot of a struct, an array or what a pointer points to like any other value, which is 8 bytes of memory of which the first 4 are the rune, read with `i32.load` and written with `i32.store`.

`F32` is a 32-bit float (`f32`) and `F64` a 64-bit float (`f64`), so JavaScript passes and receives them as plain numbers, and a number that is not exact in 32 bits is rounded to the nearest one when it is passed as an `F32`. A float literal, or a constant expression of floats, is `f32.const` or `f64.const` of its value, rounded to an `F32` where one is wanted, and as it is for an `F64`, which is what `x := 1.42` is, so it is `f64.const 1.42`, where the `wat` target writes the number with the fewest digits that read back as the same float, although the number that is stored is the nearest one, 1.4199999999999999289 for an `F64`. The arithmetic is `f32.add`, `f32.sub`, `f32.mul` and `f32.div`, and the same four of `f64`, which never trap, and the comparisons are `f32.eq`, `f32.ne`, `f32.lt`, `f32.le`, `f32.gt` and `f32.ge`, and the same six of `f64`, which are false for not a number except `ne`. A cast of an `Int` to a float is `f32.convert_i64_s` or `f64.convert_i64_s`, of a `Byte` `f32.convert_i32_u` or `f64.convert_i32_u`, a cast of an `F32` to an `F64` is `f64.promote_f32` and of an `F64` to an `F32` is `f32.demote_f64`, and a cast of a float to an `Int` is `i64.trunc_f32_s` or `i64.trunc_f64_s`, which traps, and makes the call from JavaScript throw a `WebAssembly.RuntimeError`, for not a number and for a number that is not in the range of an `Int`. The default value is `f32.const 0` or `f64.const 0`. A float is one slot of a struct, an array or what a pointer points to like any other value, which is 8 bytes of memory, of which an `F32` uses the first 4, read with `f32.load` or `f64.load` and written with `f32.store` or `f64.store`. The module has a scratch local of each of the types `f32` and `f64` after the others when a procedure uses arrays.

`I64` is a 64-bit integer (`i64`), like an `Int`, so JavaScript passes and receives it as a `BigInt`, and its arithmetic and comparisons are the same instructions, with the same traps. A cast between an `Int` and an `I64` writes nothing, and one of an `I32` to an `I64` is `i64.extend_i32_s`. `int_to_i32` takes one of them.

`I32` is a 32-bit integer (`i32`), so JavaScript passes and receives it as a plain number, and not as a `BigInt`, and so it is for a foreign procedure of JavaScript that takes or gives one. Its arithmetic is `i32.add`, `i32.sub`, `i32.mul` and `i32.div_s`, which wrap around in 32 bits, and trap for a division by zero and of the smallest number by -1, and its comparisons are the signed `i32.lt_s`, `i32.le_s`, `i32.gt_s`, `i32.ge_s`, `i32.eq` and `i32.ne`. A cast of an `I32` to an `Int` is `i64.extend_i32_s`, and to a float `f32.convert_i32_s` or `f64.convert_i32_s`. `int_to_i32` keeps the number in a scratch local, cuts it down with `i32.wrap_i64`, fills its sign in again with `i64.extend_i32_s`, traps with `unreachable` unless it is the same number, and cuts it down once more. In memory, an `I32` is the first 4 bytes of a slot of 8, as any other value that is 32 bits.

`Bool` is a 32-bit integer (`i32`), which is 0 for `false` and 1 for `true`, as a comparison in WebAssembly leaves it. So JavaScript passes a `Bool` as `true`, `false`, 0 or 1, and receives it as the number 0 or 1, which `Boolean(...)` turns into a boolean. Comparisons of `Int` values are signed `i64` instructions, and comparisons of `Bool` values with `==` and `not=` are `i32.eq` and `i32.ne`. `and`, `or` and `not` are `i32.and`, `i32.or` and `i32.eqz`, which are correct because a `Bool` is always 0 or 1.

`Str` is two 32-bit integers (`i32`): the address of its first byte in memory, and its length in bytes. The bytes are UTF-8, so a caller decodes them as that, as `TextDecoder` does by default. So a parameter of type `Str` is two WebAssembly parameters, one after the other, and a result of type `Str` is two WebAssembly results, which JavaScript receives as an array `[address, length]`. The bytes of all the string literals of the program are copied to the start of the memory of the module when it is instantiated, and so is the text that `++` joined when the program was compiled, which is a string literal to the module, and the module exports the memory as `memory`, so that a caller can read a string:

```js
const [address, length] = instance.exports.get_name();
new TextDecoder().decode(new Uint8Array(instance.exports.memory.buffer, address, length));
```

A `C_Str` is one 32-bit integer (`i32`): the address in the memory of the module of bytes that end with a zero. So a parameter of that type is one WebAssembly parameter, and a caller from JavaScript reads the bytes from the address up to the first zero. A zero is written after every string literal in the data section. `str_to_c_str` is only accepted with a string literal or a constant that is a string as its argument, and it is then only the address of the literal, `i32.const`, without the length and without a copy. For a constant it is the address of its literal, so `str_to_c_str(greeting)` does not call the function of `greeting`. An untyped string where a `C_Str` is wanted is the same address, so `show("Hello")` passes `i32.const` of the address of the bytes of `"Hello"`. Nothing else is a `C_Str`, so a `C_Str` cannot be given a value as an element of an array, a field of a struct or a global variable.

A global variable is a mutable global of the module, or two when it is a `Str`, which are the address and the length of the string, in the order of the definitions in the source. They are not exported. The initial value is the constant expression of the global, which WebAssembly evaluates once when the module is instantiated, which is why it is a constant: the compiler worked out its value, and the global is `i64.const` or `i32.const` of it, or of the address and the length of a string. The bytes of a string literal that is the value of a global variable are in the data section, as the bytes of the other string literals are. A use of a global variable is a `global.get` for each of its globals, and an assignment such as `x += 2` pushes it with `global.get`, then the value, adds them and stores the result with `global.set`. So a global variable keeps its value from one call of the exported functions to the next, for as long as the instance lives.

A foreign procedure is an imported function, which the module gets from the object of imports when it is instantiated, see [foreign procedures](#foreign-procedures). The imported functions come before the other functions of the module, because WebAssembly numbers them first, so a foreign procedure has the index of its place among the foreign procedures, and any other procedure has the number of foreign procedures plus its place among the others. That index is what the `call` instruction has, so it is not the place of the constant in the source. The module has an import section, with one function for each foreign procedure, whose type is the signature of the declaration, and the type section lists the types of the imports before the ones of the other functions. A foreign procedure has no export and no code of its own, and a program that has no foreign procedure has no import section.

The variables of a procedure are locals of its function, after the parameters, and a `Str` variable is two locals, like a `Str` parameter. The exception is a variable whose address is taken, which is in the frame, see below, and has no locals. The variables of the blocks of if statements and for statements are locals of the function too, each one a local of its own, after the ones above it, also when two variables have the same name in different blocks. The definition of a variable stores the initial value in them, and an assignment such as `x += 2` pushes the value of the variable, then the value, adds them and stores the result in the local of the variable. The assignment `x /= y` traps in the same cases as the division `x / y`.

An array literal that fills, `[5]Int { .. = 0 }`, works out its value once and stores it in the first element, which is its place in the frame like any literal, and a loop of `memory.copy`, one element at a time, copies it to each of the others, with a destination that moves on by the size of an element and a count that goes down to 0. An array of no elements drops the value. The loop keeps its destination and its count in scratch locals.

An array is stored in the memory of the module, on a stack that grows down from the end of the memory, and not in locals, because an array slice refers to elements by their address. A procedure that has array literals, or variables whose address is taken, makes room for the elements of all of them when it starts, by moving a stack pointer, which is a mutable global of the module that comes after the globals of the program, and moves it back before it returns. The room is the frame of the procedure. Every value of an element takes 8 bytes in memory, also a 32-bit one, so an element takes 8 bytes for each value it is made of, see below for structs. A variable of an array type is a local that holds the address of its first element, and its length is part of the program: the code that needs it, such as a bounds check, has it as a constant. An array literal stores each of its elements at its place with `i64.store` or `i32.store`, and leaves the address of the first one, which is the stack pointer of the procedure plus the offset of the literal. The stack is 1 MiB. A call that would need more traps, by comparing the new stack pointer with the end of the stack. After a trap the stack pointer is not moved back, since nothing runs to do it, so an instance that has trapped has less stack left, and a program should make a new one.

An array slice is two 32-bit integers (`i32`), like a `Str`: the address of its first element and its number of elements, and a parameter of that type is two WebAssembly parameters. A caller from JavaScript writes the elements, which are `BigInt64Array` elements for `Int` values, to the memory that the module exports as `memory`, and passes the address and the length:

```js
new BigInt64Array(memory.buffer, 0, 3).set([10n, 20n, 30n]);
sum(0, 3);
```

An array is made into a slice where one is wanted by writing its length after its address, which is `i32.const` and the length. A subscript traps unless the index is below the length, which is one unsigned 64-bit comparison, so a negative index and one that does not fit in 32 bits trap as well. Then the address of the element is the address of the first plus the index times 8, and the element is loaded with `i64.load` or stored with `i64.store`. A slice with two bounds traps unless the low bound is not above the high bound, and the high bound is not above the length, and its address is moved up by the low bound, and its length is the difference between the bounds. The assignment to a range of elements is a `memory.copy`, after a comparison of the two lengths, so the module needs an engine that supports bulk memory operations, which all current browsers and Node.js do. The code of subscripts, slices and assignments to elements keeps values between instructions in locals after the variables of the procedure, which a procedure that has any of them gets: two 64-bit locals and three 32-bit ones, the last of which holds the address of the frame.

A for statement that goes through the elements of an array or a slice is the same three structured instructions as one with a range, with two 32-bit locals after the iterator: the address of the next element and the address after the last one. Before the loop the end is stored, which is the address plus the length times 8. The loop begins with a test that leaves the `block` with `br_if` when the next address is not below the end. The iterator is loaded from the next address, and the address moves up by 8 before the statements of the block, so what comes after the second `block`, where `continue` goes, is only the `br` back to the start of the `loop`.

A struct is made of the values of its fields, one after the other, in the order of its definition, where a field that is a struct takes its own fields in its place, and nothing else: it has no header and no padding. So a `Person` is three values, the `i64` of the age and the `i32` address and `i32` length of the name. A parameter of a struct type is that many parameters, a variable is that many locals, and a procedure that returns a struct has that many results, which JavaScript receives as an array, in the order of the fields. Reading a field of a variable or a parameter is a `local.get` for each of its values, with no cost for the rest of the struct, and assigning to a field is a `local.set`; a struct literal pushes the values of the fields in the order of the struct, with the default value, which is zero, for every field when its braces are empty. The values of a struct literal are written in the order of the fields of the struct, so a string in a literal can have its address in the data section before one that comes before it in the source, which the address of a string allows, since it is the length of the strings before it in the source. A struct in an array is in memory, with 8 bytes for each of its values, so `Person` takes 24 bytes there. The field of an element is read with a load at the address of the element plus 8 times the number of values before the field, and is assigned with a store there. An assignment of a whole struct to an element is a store of each of its values, with the last on the stack stored first, using a local to hold each value while the address is pushed below it. A default value is `i64.const 0` or `i32.const 0` for each value. A struct is not a function: the definition of one is a constant that has no code and no export.

A `Byte` is one 32-bit integer (`i32`) whose value is from 0 to 255, so a parameter of the type is one WebAssembly parameter and a result is one result, which JavaScript passes and receives as a plain number and not as a `BigInt`. An untyped integer that is a `Byte` is `i32.const`. Bytes are compared with the unsigned instructions `i32.lt_u`, `i32.le_u`, `i32.gt_u` and `i32.ge_u`, and with `i32.eq` and `i32.ne`. `byte_to_int` is `i64.extend_i32_u`. `int_to_byte` keeps the number in a local, compares it with 255 as an unsigned 64-bit number with `i64.gt_u`, which also finds a negative number, traps with `unreachable` when it is above, and otherwise is `i32.wrap_i64` of the number. The default value is `i32.const 0`. The elements of an array of `Byte` and what a pointer to a `Byte` points to take one byte of memory, not 8 as the others do: an element is read with `i32.load8_u` and written with `i32.store8`, the address of an element is the address of the array plus the index with no scaling, and a `for` statement moves its address up by 1. So a `Uint8Array` of the memory of the module is the array: `new Uint8Array(memory.buffer, 0, 3).set([1, 2, 3])` and then `sum_of_bytes(0, 3)`. The elements of the array literals in the frame of a procedure, and its variables, are each rounded up to a multiple of 8 bytes, so that what comes after them is aligned. A `Byte` that is a field of a struct is one value of the struct, and in memory it takes the 8 bytes of any value, from which `i32.load8_u` and `i32.store8` use the first.

A pointer is one 32-bit integer (`i32`): the address in the memory of the module of what it points to, so a parameter that is a pointer is one WebAssembly parameter, and a result that is a pointer is one result, which JavaScript passes and receives as a number. `nil` is `i32.const 0`, which is also what a pointer that is not given a value is, and is not the address of anything that a program can point to. Two pointers or a pointer and `nil` are compared with `i32.eq` and `i32.ne`, as two `Bool` values are. What a pointer points to is in memory like an element of an array: 8 bytes for each of its values, aligned, so a `Str` takes 16 bytes and a struct takes 8 for each of its values, and the first four bytes of the 8 hold a 32-bit value. A field that is a pointer is one value of the struct, and so is an element of an array that is a pointer. A caller from JavaScript can point to what it wrote to the memory of the module, as it does for the elements of a slice:

```js
new BigInt64Array(memory.buffer)[1] = 41n;
increment(8);
```

A variable whose address is taken, as in `%x` or `%x.field`, is not in locals, because a local has no address, but in the frame of its procedure, after the elements of its array literals: each variable has a place of its own, also when it is in a block, in the order of the source, and takes 8 bytes for each of its values. The analysis found out which variables these are, see `Semantic_Binding`. The definition of such a variable stores its initial value in its place, with the last value on the stack stored first, using a local to hold each value while the address is pushed below it. A use loads the values from there, an assignment stores to there, and `%x` is the frame plus the offset of the variable, so that the variable and the pointer are the same memory. The address of a field is that plus 8 times the number of values before the field, and the address of an element is the address that a subscript computes, with the same trap for an index outside of the array. The address of a variable is good until its procedure returns and the frame is given back, after which a pointer to it points to the stack of whoever is called next.

`p^` follows a pointer by holding it in a local, trapping if it is 0, and loading the values of what it points to from it, one `i64.load` or `i32.load` for each, with the offset of the field in front of it for `p.age`, which is how a field of a pointer to a struct is read, written with or without the `^`. The pointer that is followed is the one before the last dot that is after a pointer, so `node.next.value` loads the pointer `node.next` first and then the field `value` from what it points to. The trap is an `if` with `unreachable` after a test with `i32.eqz`, which makes the call from JavaScript throw a `WebAssembly.RuntimeError`, and is needed because address 0 is where the strings start, and a null pointer would read them instead of stopping the program. An address that is outside of the memory traps as well, which is what WebAssembly does for any load or store. An assignment through a pointer evaluates the pointer first, checks it and keeps it in a local while the value is evaluated, like the address of an element is kept, and then stores to it. The operators such as `p^ += 1` load from the pointer, apply the operator and store the result to the same address. Nothing else is done for a pointer: it is copied by copying the number, so a procedure gets a pointer to the same memory as its caller.

A pointer to a procedure is one 32-bit integer (`i32`) as well, but it is not an address in the memory: it is the index of the procedure in the table of the module. The table has a slot for every function of the module, the imported ones too, put there by an element segment in the order of the function indexes, from slot 1 on. Slot 0 has no function, so the number 0, which is `nil` and what a pointer that was not given a value is, is the pointer that can be called to no effect but a trap. So the pointer to a procedure is its function index plus one, and the name of a procedure that is not called is `i32.const` of that. A call through a pointer is the arguments, then the pointer, and `call_indirect` with the type of the procedures that the pointer can point to and table 0. WebAssembly checks that the function in the slot has that type, and it traps, which makes the call from JavaScript throw a `WebAssembly.RuntimeError`, when the slot is empty, as it is for `nil`. The type is the type of the function of the first procedure that has the parameters and result of the pointer, and when there is none that comes first, a type of its own that the type section has after the types of the functions. The module has a table and an element segment only when the program uses a pointer to a procedure, which is when it has such a type or uses a procedure by its name without calling it. A pointer to a procedure can be kept in memory like any pointer, so `^^proc(Int) Int` and the elements of an array of them take 8 bytes each. JavaScript has no way to get a pointer to a procedure from the module, but it can pass the number of a slot, which is the function index plus one.

A procedure that returns several values is a function with several results, one for each of its values in the order of its return types, where a `Str` is two results, so JavaScript receives them as an array. `divide(31, 4)` gives `[7n, 3n]`, and a procedure that returns a `Bool`, a `Str` and an `Int` gives `[1, address, length, 5n]`. A `return` leaves its values on the stack in the order that they are written, and a call leaves all of them, so the definition of several names, `quotient, remainder := divide(31, 4)`, stores them into the locals of the variables from the last name to the first, and a call that is a statement drops each of them. A name `_` is stored in a local that nothing reads. A pointer to a procedure with several return types is an index in the table, and `call_indirect` has the type with all of the results, so two such pointers are of one type when their results are the same types in the same order.


An enum is one `Int` (`i64`), which is the number of the member, counted from 0 in the order of the definition. So a parameter of an enum type is one WebAssembly parameter and a result is one result, which JavaScript passes and receives as a `BigInt`, so `Color.GREEN` is `1n`. A member that is written `Color.GREEN` or `.GREEN` is `i64.const` of its number, which is worked out when the module is built, from the enum that the place of `.GREEN` wants. A constant that is a member is a function without parameters that returns the number, like a constant that is a string, and is exported under its name. Members are compared with `i64.eq` and `i64.ne`, and the default value of an enum type is `i64.const 0`. A field of an enum type is one value of a struct, and the elements of an array of enums and what a pointer to an enum points to take 8 bytes each, like those of any other type. An enum has no code of its own, as a struct has not, so it is not exported and is no function.


A module has a memory only when the program has a string literal, which includes the value of a global variable, an array type, which includes the array literals and the array slices, `type_info_of`, or a pointer: a pointer type, `%` or `^`. The strings are at the start of the memory, then the information of `type_info_of`, and the stack of the arrays is after them.

`type_info_of(Color).members` is an array in the data of the module, after the strings and at an address that is a multiple of 8, and the value of the expression is `i32.const` of that address, as any array is the address of its first element. Its elements are `Enum_Member_Type_Info` structs, which take three slots of 8 bytes each: the address and the length of the name, which are 32-bit numbers in the first two slots, and the number of the member, a 64-bit one, in the third. The bytes of the name of the enum and of the members come after the array. A global variable that is given the members is an `i32` global that has the address, and `type_info_of(Color).name` is the address and the length of the name, as for any `Str`. Every use of `type_info_of` has an array of its own, even for an enum that has one already. `length_of` of an array is the `i64.const` of its length, with the array itself written first, and the length of a slice is the second of its two values, extended to 64 bits, with the address dropped. A procedure cannot be called `memory`, whether the module has one or not, because that is the name of the export.

The target rejects a program that the parser accepts when:

- the type written after `enum` is not `Int`,
- `type_info_of` is asked about a type that is not an enum, or is not followed by `.name` or `.members` right away, or is the initial value of a global variable with anything more than one of them after it,
- a `return` gives another number of values than the procedure has return types, or a call that returns several values is used where one value is wanted, such as an argument or the value of a variable with one name, or the definition of several names is not of a call, or the call returns another number of values than there are names, or a return type is a type that the target does not have,
- `length_of` has other than one argument, or an argument that is not an array, an array slice or a `Str`, or a `Str` is subscripted with an index that is not an `Int`, or `try_str_to_int` has an argument that is not a `Str`, or `utf8_decode` has an argument that is not an array or an array slice of `Byte`, or either is not the value of a definition of two names, or `int_to_i32` has an argument that is not an `Int`, or the operands of arithmetic or a comparison are of two of `Int`, `I32` and `I64`, or an operand of a comparison of arrays is not an array or an array slice of `Byte`, or the comparison has an order,
- `cast(Type)` casts to another type than `Int`, `Rune`, `F32`, `F64` or `[4]Byte`, or a value that is not a `Byte`, a `Bool`, an `Int`, a `Rune` or a float to `Int`, or not a `Byte`, an `Int` or a float to a float, or not a `Byte` or a `Rune` to `Rune`, or not a `Rune` to `[4]Byte`, and `int_to_byte` has other than one argument, or an argument that is not an `Int`,
- a type, also the one of a global variable, is not `Int`, `F32`, `F64`, `Rune`, `Bool`, `Byte`, `Str`, a struct or an enum that is defined, a pointer to one of them, or an array or an array slice of one of them, or a struct has a field of such a type, or the name of the struct in a struct literal is not one that is defined,
- a struct contains itself, or has a field that is an array or an array slice,
- a field of a struct literal is not a field of the struct, or is given twice, or its value is not of the type of the field, or the literal gives a value to some fields and not to all of them,
- a field is accessed on a value that is not a struct or a pointer to one, or does not exist, or is accessed through something that is not a variable, a parameter, an element of an array or a pointer,
- a field is assigned through a parameter or an iterator that is not a pointer,
- a value that is assigned with `=` is not of the type of the variable, the field, the element or what the pointer points to,
- `^` follows a value that is not a pointer,
- the operand of `%` has no address: it is a value that is computed, a parameter, the iterator of a for statement, a global variable, an array or an array slice, or a variable of an array or array slice type,
- the type of a parameter is an array, or the type of a global variable is an array, an array slice or a pointer, which can be given no constant for its initial value,
- an array literal has another number of elements than the length of its type, or a variable of an array type with a length has another number than that,
- a variable of an array type is not given an array literal,
- an element of an array literal, or the value that is assigned to an element, is not of the type of the elements,
- what is subscripted, sliced or gone through by a for statement, or what is copied to a range of elements, is not an array or an array slice, or an index or a bound is not an `Int`,
- a name in an expression, or the initial value of a variable, is a struct, which is a type and not a value,
- a call is of a variable, a parameter or a global variable that does not hold a pointer to a procedure,
- `^` follows a pointer to a procedure, or `%` is given the name of a procedure, which has no address,
- a type in the parameters or the return type of a pointer to a procedure is not one that the target has,
- the initial value of a global variable is not of the type that is written for the variable, or is untyped and does not fit in it, or the type is `C_Str`,
- a definition is called `memory`,
- a procedure with no return type has a `return` statement,
- the value that a procedure returns is not of its return type,
- the initial value of a variable is not of the type that is written for the variable,
- a call has a different number of arguments than the procedure has parameters, or an argument is not of the type of its parameter,
- the call of a procedure without a return type is used as a value, and not as a statement,
- an operand of an arithmetic operator is not an `Int` or not a float, or the operands are of different types,
- the operands of a comparison are not both `Int`, both `Rune` or both floats of one type, or not both `Bool`, both `Str` or both pointers or both members of one enum (or `nil`) for `==` and `not=`,
- the value of a variable that is defined without a type is `nil` or a member such as `.RED` that is written without its enum, which does not say the type of the variable,
- a member such as `.RED` is where no enum is known, or the enum has no such member, or it is the member of a name that is not an enum,
- the operands of a comparison are members of two enums, or members of an enum are compared with `<`, `<=`, `>` or `>=`,
- an operand of `and`, `or` or `not` is not a `Bool`,
- the condition of an if statement is not a `Bool`,
- the subject of a match statement is not an `Int`, a `Byte`, a `Str` or an enum, a pattern is not a constant or not of the type of the subject, a range is empty or is the pattern of a `Str` or an enum, two cases match a value in common, a match of an enum without a default case and without `partial` has no case for a member, or a match with `partial` is not of an enum or has a default case,
- the first number or the end of a range is not an `Int`,
- the variable or the value of an assignment such as `x += 2`, `x -= 2`, `x *= 2` or `x /= 2` is not an `Int`, or not a float, or they are of different types.

The target is built from the result of scope resolution, so it also rejects every program that scope resolution rejects.

An if statement becomes the structured instructions of WebAssembly: the condition, which leaves 1 or 0 (for a comparison, its two operands and the signed comparison of them), then `if`, the block, `else` and the next branch, up to `end`. An `else if` is written as an `else` with another `if` in it, so the statement ends with an `end` for each of its conditions. When the last statement of a procedure that returns a value is not a `return`, for example an if statement that returns in all of its branches, the body ends with the `unreachable` instruction, because WebAssembly cannot tell that the end of it cannot be reached. A body that gets there anyway traps.

A subscript of a string, `s[i]`, takes the address, the length and the index off the stack into scratch locals, and walks over the first `i` characters with a `block` that holds a `loop`: each step moves the address on by one byte, and then over the bytes that have the bits 10 at the top, which are the rest of a character, found with `i32.and` of 0xC0 and `i32.ne` of 0x80. It traps with `unreachable` when the address reaches the end before the characters are used up, and when it is at the end afterwards. The first byte of the character that it stops at says how many bytes continue it, in comparisons with 0xC0, 0xE0 and 0xF0, which also give the bits of the first byte that are part of the code point, and a loop puts the low 6 bits of each byte that continues it after them with `i32.shl` and `i32.or`. The `Rune` is the `i32` that is left. `length_of` of a string counts the bytes that do not have the bits 10 at the top.

A slice of a string, `s[low:high]`, takes the address, the length and the two bounds off the stack, traps with `unreachable` unless `low` is not above `high`, which is an unsigned `i64.gt_u`, and walks to the character at `low` the way a subscript does, which is where the new string starts. It then walks over `high - low` more characters, and the new string is that address and the number of bytes between the two addresses. Nothing is copied.

A for statement over a string is written like the one over the elements of an array, with the address of the next byte and the address after the last one in two locals after the iterator, which is a `Rune`, an `i32`. The loop starts with a test that leaves the `block` when the next address is not below the end, and then the character at the next address is decoded into the iterator, the way a subscript does it, which also moves the address past it. The statements of the block are in a `block` of their own that `continue` leaves.

The built-in procedure `utf8_decode` leaves three results: the address and the length of the string, which are the ones of its argument or 0 and 0, and an `i32` that says whether the bytes are valid. The address and the length are taken off the stack into scratch locals, and a `block` that holds a `loop` goes over the bytes: a byte below 0x80 is a character, and for any other first byte the number of bytes that continue it is found with comparisons of the byte less the start of a range, as an unsigned number, with `i32.sub` and `i32.le_u`, for 0xC2 to 0xDF, 0xE0 to 0xEF and 0xF0 to 0xF4. A byte in none of them, the bytes that are cut off by the end, a second byte that is out of its range after 0xE0, 0xED, 0xF0 and 0xF4, and a byte that continues it without the bits 10 at the top, leave the `block` with `br`, after the address of the next byte is made -1, which is never the end. The bytes are valid when the address is the end afterwards, and the address and the length are multiplied by that, so they are 0 when it is not.

The built-in procedure `try_str_to_int` leaves an `i64`, the number, and an `i32`, whether the text was one, which are two results like those of a procedure that returns two values. Its argument is taken off the stack into scratch locals, the address of the next byte and the address after the last one, and a `block` that holds a `loop` goes over the bytes: each is read with `i32.load8_u`, the code of 0 is taken off it with `i32.sub`, and a digit above 9, which is compared as an unsigned number with `i64.gt_u`, leaves the `block`. The number is built as a negative one, with `i64.mul` by 10 and `i64.sub` of the digit, and before each digit it is compared with the smallest `Int` divided by 10, and a number that is below it, or equal to it with a digit above 8, leaves as well, because WebAssembly has no overflow flag. A number without a `-` is negated at the end, after a comparison with the smallest `Int`. The number is multiplied by the flag, so it is 0 for text that is not a number.

A comparison of two arrays or array slices of bytes with `==` or `not=` is written the same way as one of two strings, because an array that is compared is made an array slice by writing its length after its address, as it is where it is given to a procedure, so the stack has an address and a length for each operand, whichever it is.

A comparison of two strings with `==` or `not=` compares their lengths, and then their bytes. The two strings are on the stack as an address and a length each, and they are taken off it into scratch locals: the two addresses, which move along the strings one byte at a time, the address after the last byte of the first string, and a flag that says whether the strings are the same so far, which starts as the comparison of the lengths. A `block` that holds a `loop` leaves with `br_if` when the flag is 0 or the first address is at the end, and otherwise compares a byte of each with `i32.load8_u` and `i32.ne`, clears the flag for a byte that differs, and goes on with `br`. The result is the flag, or its `i32.eqz` for `not=`.

A match statement computes its subject and stores it in locals of its own, as many as a variable of its type has, after the variables above it, so that it is computed once. The cases become a chain of `if` and `else`, like an if statement that has an `else if` for each case, and the default case is the last `else`. The condition of a case is a comparison of the locals with its pattern: `i64.eq` for an `Int` and for the number of a member of an enum, `i32.eq` for a `Byte`, and for a range a comparison with each end, `i64.ge_s` and `i64.le_s`, or `i32.ge_u` and `i32.le_u` for a `Byte`, joined by `i32.and`. The cases that share a block have one condition, which joins theirs with `i32.or`. A `Str` is compared with a string pattern by its length first, and when the length is equal by a loop that compares the bytes one at a time with `i32.load8_u`, and leaves at the first that differs, so a `Str` subject has two 32-bit locals more, for the index of the byte and for whether the strings are equal so far. The empty string is compared by its length only.

A for statement with a range becomes a `block` that holds a `loop`, and the statements of its block are in a second `block` inside the `loop`. The iterator is a local, and the end of the range is a local right after it, which is where the end is read once. First the start and the end are stored, then the loop begins with a test that leaves the `block` with `br_if` when the iterator is not below the end, or above it for an inclusive range. After the statements of the block, which the second `block` ends, the iterator is increased by one and `br` goes back to the start of the `loop`. A `continue` is a `br` to the end of the second `block`, so the increase is not skipped, and a `break` is a `br` to the end of the first. An infinite loop is the same three instructions without the test and the increase, with a `br` back to the start of the `loop`. A scope statement becomes a `block`, and a `break` that leaves it is a `br` to the end of it. An if statement with a label is inside a `block` of its own, which a `break` with the label leaves, so the `block` ends after the last `end` of the statement. The number in a `br` is the number of structured instructions between it and its target, which counts the `if` instructions of the if statements that the jump is in, one for each scope or labeled if statement that it is in and has to leave on the way, and three for each loop, because a loop is a `block`, a `loop` and a `block`. A label of a loop or of a scope has no instruction of its own: it only tells which `block` the `br` goes to. For an inclusive range the loop leaves the `block` before the increase when the iterator is equal to the end, so an inclusive range that ends at the largest `Int` stops instead of wrapping around.

A [defer statement](mialu-programming-language.md#defer) writes no instructions where it is. The instructions of its deferred statement are written again at each place where its block is left: before the end of the block, which is before the `end` of the `block` of a scope and before the second `block` of a loop ends, and before each `br` of a `break` or a `continue` and each `return` below the `defer` that leaves the block. A jump writes the deferred statements of each block that it leaves, the innermost block first and in each block the last `defer` first, and then its `br`, whose number counts the structured instructions as before. A `return` writes its value first, then the deferred statements, which leave the stack as they found it, so the value is still on top, and then gives the frame back and returns. A block whose last statement is a jump writes no deferred statements at its end, which is never reached. A procedure without a `defer` gets the same instructions as it would without the statement in the language.

The `wat` target writes the same module in the WebAssembly text format, so that it can be read. It rejects the same programs as the `wasm` target.
